# digestの更新

[English](requirements.md)

## この文書について

`run --update`は、すでにdigestがある参照を解決し直します。`--min-age`は、最近ビルドされたイメージを見送ります。
継続的で自動的な更新は、[dockerfile-pin](../../product.ja.md)の原則のとおりRenovateに任せます。この機能は手動で解決し直すためのものです。

### スコープ

- `run`の`--update`（`-u`）。
- `run`の`--min-age`と、設定ファイルの`min-age`。

### スコープ外

- タグを変えること。更新するのはdigestだけで、タグは書かれたままです。
- 更新の予約や、プルリクエストの作成。
- `run`のそのほかの部分: [pin](../pinning/requirements.ja.md)。

## ユーザーストーリー

### pin済みのdigestを新しくする

開発者として、既存のdigestを解決し直したい。動いたタグを、今のイメージにpinするためだ。

**受け入れ条件:**

シナリオ: `--update`があるとき、既存のdigestをタグの今のdigestに置き換える

- 前提: ファイルに`FROM node:20.11.1@sha256:<old>`があり、タグは今`<new>`を指している。
- 操作: 開発者が`dockerfile-pin run --write --update`を実行する。
- 結果: その行が`FROM node:20.11.1@sha256:<new>`になる。

シナリオ: `--update`がないとき、既存のdigestを残す

- 前提: 同じファイルがある。
- 操作: 開発者が`dockerfile-pin run --write`を実行する。
- 結果: その行は変わらない。

### 新しいイメージを使う前に待つ

開発者として、この数日以内にビルドされたイメージを飛ばしたい。公開されてからしばらく経ったイメージだけをpinするためだ。

**受け入れ条件:**

シナリオ: イメージが期間内にビルドされているとき、pinしない

- 前提: `nginx:latest`が2日前にビルドされている。
- 操作: 開発者が`dockerfile-pin run --write --update --min-age 7`を実行する。
- 結果: `skipped nginx:latest (built <date>, within 7 days)`が表示され、その行は変わらない。

シナリオ: イメージにビルド日がないとき、pinする

- 前提: 一部の再現可能ビルドのように、イメージの設定に作成時刻がない。
- 操作: 開発者が`dockerfile-pin run --write --min-age 7`を実行する。
- 結果: そのイメージはpinされる。

シナリオ: ビルド日を読めないとき、警告を出してpinする

- 前提: イメージの設定の読み取りが失敗する。
- 操作: 開発者が`dockerfile-pin run --write --min-age 7`を実行する。
- 結果: `WARN  <image>  failed to get creation time, pinning anyway: ...`が表示され、そのイメージはpinされる。

シナリオ: `--min-age`が負の数のとき、コマンドは失敗する

- 前提: 任意の対象ファイルがある。
- 操作: 開発者が`dockerfile-pin run --min-age -1`を実行する。
- 結果: コマンドは`--min-age must be a non-negative integer`で終了する。

## 機能要件

### 更新

**概要:** `--update`があると、digestのある参照も、ない参照と同じように解決します。

**入力:** `--update`か`-u`。

**出力:** 既存のdigestを、タグが今指しているdigestに置き換えたもの。

#### 適用条件

イメージは、`@`より前に書かれた名前とタグで解決します。スキップした参照と除外した参照は更新しません。

### 最小の経過日数

**概要:** ビルド日がこのN日以内のイメージは、その実行から外します。

**入力:** `--min-age N`か、設定ファイルの`min-age: N`。両方あるときはフラグが優先されます。既定は0で、この確認をしません。

**出力:** 期間より新しいイメージは、pinも更新もしません。

#### 適用条件

ビルド日は、イメージの設定にある作成時刻です。
この期間は、`--update`の有無にかかわらず、`run`が解決するすべてのイメージに当てはまります。

## データ要件

### 必要なデータ

- **ビルド日:** 解決した各イメージの作成時刻。期間を設定したときだけ読みます。

## 外部サービスへの依存

- **コンテナレジストリ**
  - **関連するユーザーストーリー:** すべて。
  - **依存する理由:** 今のdigestとイメージの設定はレジストリにしかないため。
  - **契約と利用上の判断:** `--min-age`を使うと、HEADリクエストに加えてイメージの設定を取得するので、レジストリへのリクエストが増えます。

## セキュリティ上の考慮事項

最小の経過日数は、様子を見る期間です。既存のタグにpushされた改ざんイメージは、その期間公開されたままでなければ取り込まれません。
