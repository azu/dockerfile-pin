# 除外と設定

[English](requirements.md)

## この文書について

この機能は、プロジェクトがglobパターンでイメージを`run`と`check`の対象から外し、設定を設定ファイルに置けるようにします。
親のProductは[dockerfile-pin](../../product.ja.md)です。

### スコープ

- `run`と`check`の`--ignore-images`。
- `.dockerfile-pin.yaml`と、そのキー`ignore-images`と`min-age`。

### スコープ外

- `min-age`が何をするか: [digestの更新](../digest-updates/requirements.ja.md)。
- ファイルを除外すること。パターンが一致するのはイメージで、パスではありません。
- `--glob`や`--verify-tag`など、ほかのオプションを設定ファイルで指定すること。

## ユーザーストーリー

### pinしたくないイメージを除外する

開発者として、社内のイメージなど一部のイメージを除外したい。`check`がそれで失敗せず、`run`がそれをpinしないようにするためだ。

**受け入れ条件:**

シナリオ: イメージがパターンに一致するとき、`check`はスキップする

- 前提: ファイルにdigestのない`FROM ghcr.io/myorg/app:v1`がある。
- 操作: 開発者が`dockerfile-pin check --ignore-images "ghcr.io/myorg/*"`を実行する。
- 結果: その参照は`ignored`付きの`SKIP`として報告され、失敗の原因にならない。

シナリオ: イメージがパターンに一致するとき、`run`は変えない

- 前提: 同じファイルがある。
- 操作: 開発者が`dockerfile-pin run --write --ignore-images "ghcr.io/myorg/*"`を実行する。
- 結果: そのイメージは解決されず、その行は変わらない。

シナリオ: 後ろの否定パターンが一致するとき、そのイメージはまた検査される

- 前提: パターンが`ghcr.io/myorg/*`、`!ghcr.io/myorg/public-*`の順にある。
- 操作: `check`が`ghcr.io/myorg/public-api:v1`と`ghcr.io/myorg/private:v1`を読む。
- 結果: 1つ目は検査され、2つ目はスキップされる。

シナリオ: パターンが正しくないとき、コマンドはファイルを読む前に失敗する

- 前提: 閉じていない`[`を含むパターンがある。
- 操作: 開発者が`dockerfile-pin check --ignore-images "[abc"`を実行する。
- 結果: コマンドは`invalid ignore pattern "[abc"`で終了する。

### 設定をリポジトリに置く

開発者として、除外の規則をファイルに置きたい。手元の実行とCIが同じ規則を使うようにするためだ。

**受け入れ条件:**

シナリオ: 設定ファイルがあるとき、そのパターンが使われる

- 前提: 現在のディレクトリの`.dockerfile-pin.yaml`に`ignore-images: ["scratch", "mcr.microsoft.com/**"]`がある。
- 操作: 開発者が`--ignore-images`なしで`dockerfile-pin check`を実行する。
- 結果: 一致するイメージは`ignored`としてスキップされる。

シナリオ: ファイルとフラグの両方にパターンがあるとき、フラグのパターンが後ろに来る

- 前提: ファイルに`ghcr.io/myorg/*`がある。
- 操作: 開発者が`dockerfile-pin check --ignore-images "!ghcr.io/myorg/app:*"`を実行する。
- 結果: `ghcr.io/myorg/app:v1`は検査される。

シナリオ: 設定ファイルがYAMLとして正しくないとき、コマンドは失敗する

- 前提: `.dockerfile-pin.yaml`を解析できない。
- 操作: 開発者が`dockerfile-pin check`を実行する。
- 結果: コマンドは`parsing .dockerfile-pin.yaml: ...`で終了する。

## 機能要件

### 除外パターン

**概要:** イメージは、最後に一致したパターンが否定でなければ除外されます。

**入力:** 設定ファイルのパターンと、それに続く`--ignore-images`の値。この順に並びます。フラグは繰り返し指定でき、1回の指定が1つのパターンです。

**出力:** イメージごとの、除外するかどうか。

#### 適用条件

パターンはdoublestarのglob構文を使い、イメージ全体に一致する必要があります。`*`は`/`をまたがず、`**`はまたぎ、`?`は1文字に一致します。
`!`で始まるパターンは否定です。
一致させる文字列は、digestと`docker://`の接頭辞を除き、`FROM`では`ARG`を展開した後のイメージです。たとえば`node:*`は、参照にdigestがあってもなくても`node:20`に一致し、`scratch`は`scratch:latest`に一致しません。
読み取りがすでにスキップしている参照は、そのスキップの理由のままです。

### 設定ファイル

**概要:** 設定は、現在のディレクトリの`.dockerfile-pin.yaml`から読みます。それがなければ`.dockerfile-pin.yml`から読みます。

**入力:** ファイルの`ignore-images`（パターンの一覧）と`min-age`（日数）。

**出力:** 設定。ファイルがなければ設定なしです。

#### 例外時の振る舞い

読めないファイルや解析できないファイルがあると、コマンドはエラーで止まります。上の2つ以外のキーは使いません。

## データ要件

### 必要なデータ

- **設定:** パターンと最小の経過日数。各コマンドの開始時に読みます。

## セキュリティ上の考慮事項

除外したイメージは検査されないので、広いパターンはpinしていないイメージを隠すことがあります。否定パターンを使うと、広く除外する代わりに、狭い例外を書けます。
